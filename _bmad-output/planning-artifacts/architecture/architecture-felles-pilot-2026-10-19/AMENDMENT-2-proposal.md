# Amendment 2 (approved by Jo with Option A, applied) — branching unit, seams and the S00 bootstrap

Status: **approved by Jo on 2026-10-19 (Option A; all clarifications, acknowledgements, the 65-to-75 story split, and the fast-forward timing of `planning/felles` into `main` immediately before S00 begins) and applied to `ARCHITECTURE-SPINE.md`.** The proposal text below is kept as the record.

## The defect (confirmed twice)

AD-20 and AD-26 (as amended by Amendment 1) tag, ledger and trace at **slice** granularity (`sNN-integrated`, `FELLES_SLICE`, "every evidence part of the slice"). The spine's Git convention says "**one story**, one branch, one worktree", and the epics derived from it merge per story. Consequence: the first story of any slice (2.1, 3.1, 4.1, 5.1, 6.1, 7.1, and the very first S00 story) cannot pass the gate, because the verification set demands evidence parts that later stories of the same slice deliver; and if one were forced through, the incomplete slice would enter every other candidate's verification set and destroy the S01 ∥ S02 independence. A prototype of the slice-level rule failed the first S00 story (`BOK-02@1.2, BR-4@1.3` missing), and a story-level variant passed 14 of 14 scenarios.

## Decision 1 — which unit lands on `main` (choose one)

**Option A (recommended): the slice is the integration unit.** One agent works a slice on `slice/sNN` in one worktree, which is how the PRD already describes the ramp (PIL-06: "two agents for S01 ∥ S02 in separate worktrees"). Stories are serial commits (or short `story/N.M` branches merged into the slice branch after `npm run verify`, the story's own tests and the ownership check). The merge gate lands the whole slice on `main` once, when every evidence part of the slice passes; Amendment 1 stays exactly as applied. Cost: `main` moves eight times; an intermediate story is not visible on `main` until its slice lands.

**Option B: the story is the integration unit.** Keep per-story merges to `main`. This needs story-level ledger rows and tags (`story-N.M-integrated`), `requirements.json` parts keyed by story, `FELLES_STORY` as candidate, and slice acceptance that requires every story of the slice integrated; trace logic changes accordingly (prototyped, 14/14 scenarios). More landings and earlier feedback, but a larger rewrite of AD-20, AD-26, AD-27 and Stories 1.18, 1.19.

## Decision 2 — the clarifications (all proposed with Option A; adopt or amend)

1. **Conventions → Git row.** Replace "One story, one branch, one worktree; ledger and pilot log written on main only" with: "One slice agent, one slice branch `slice/sNN`, one worktree; stories are serial commits or short story branches merged into the slice branch; the merge gate lands a whole slice on `main`; the ledger and pilot log are written on main only."
2. **AD-20 seam sentence.** Replace "the web hooks and slot stubs live in `apps/web/src/api/` (`sheet.ts`, `slots.ts`) and S04/S05 replace their bodies" with: "S00 creates a typed seam entry file in each owning feature (`features/bookings/index.tsx` exporting `BookingSheet`, `BookingDetailHost`, `AvailabilityStrip`; `features/booking-actions/index.tsx` exporting `BookingActions` with the frozen props), each a stub owned by the implementing slice in `ownership.json`. `app/providers` (S00) imports these entries once and provides them through context hooks in `api/sheet.ts` and `api/slots.ts`, which contain no feature code and are never edited by slices. A slice replaces the body of its entry file and edits neither `app/` nor `api/`." (This also keeps layering: `api/` never imports features.)
3. **AD-20 contracts freeze.** Add: "`packages/contracts/src/{activity,dashboard}.ts` and the schedule DTO exports are owned by S03 until `s03-accepted` and frozen afterwards; `ownership.json` encodes this."
4. **AD-20 routes.** Add: "Routes are split by owning slice: `modules/bookings/routes.ts` (S03: create, list, get, schedule) and `modules/bookings/transitions.routes.ts` (S05: approve, reject, cancel); `dashboard` and `activity` have their own `routes.ts`."
5. **AD-27 smoke.** Replace "the macOS job also runs `scripts/smoke.mjs` (fresh seed, start, log in, one booking, one conflict)" with: "`scripts/smoke.mjs` runs phases (seed and start, `GET /api/health`, `GET /api/session` in S00; login after S01; one booking and one refused conflict after S03), printing `PENDING <slice>` while a route answers 501; `--require-full` fails on any pending phase and is the only mode of the S07 macOS job."
6. **AD-26 and AD-27 change sets.** Add: "A change set touching only `_bmad-output/planning-artifacts/**` runs `verify` without the trace check; `requirements.json` is regenerated and committed in the same pull request with a `Freeze-Approved` trailer."
7. **AD-20 S07 edit rights.** Add: "S07 may edit any non-frozen file; each such commit carries a `Fixes: N.M` trailer naming the owning story; frozen files still need `Freeze-Approved`."
8. **AD-20 bootstrap (new paragraph).** "S00 is built by one agent on `slice/s00` branched from `main` after `planning/felles` has been fast-forwarded into `main` on Jo's instruction. Stories before the gate tooling exists are verified with `npm run verify` only. `trace.mjs` and `requirements.json` (with an empty ledger of the final format) are built before the merge gate; the first real run of the gate lands S00 as a whole-slice candidate and creates `s00-integrated`; Jo then runs `accept-slice.mjs S00`. Until `s00-integrated` exists, CI on `slice/s00` runs with `FELLES_SLICE=S00`."
9. **State vocabulary (AD-20, new paragraph).** Story state: sprint-status `backlog → ready-for-dev → in-progress → review → done`; story ledger entries `implemented`, `tested`, `reviewed` cite the slice-branch commit and are written on main by the orchestrator; agent completion is at most `implemented`. Slice state: `integrated` (landed by the gate with all slice evidence passing) then `accepted` (Jo); `accept-slice.mjs` sets all stories of the slice to `done` in the same act, so there is one acceptance. Requirement state is computed: an evidence part passing at an integrated slice is `evidenced`, at an accepted slice `verified`.

## Decision 3 — items for acknowledgement (no spine change)

- **Contract checkpoint as a gate.** Make "Jo contract checkpoint" an explicit gate (Story 1.4-CP) that Stories 1.5 onward depend on, recording the route table, DTO list, schema snapshot hash and a contracts content hash; the S00 freeze package must show the hash unchanged or re-approved. This is the approved PIL-09 reading (checkpoint after T00-02), now enforced.
- **Schema upfront.** Story 1.4 creates the whole schema although the skill's rule is "tables when needed". Justified by AD-19, PIL-06 (schema frozen and approved before parallel work), cross-table triggers that are only reviewable as a unit, SEED-1 and migration-range collisions. To be stated in Epic 1 and Story 1.4.
- **Foundation epic.** Epic 1 (21 stories, process tooling included) is a technical milestone justified by the greenfield start, the approved enlargement of S00 and PIL-06; to be stated, with Stories 1.18/1.19 labelled delivery controls.
- **Story splits.** Split the five largest stories (1.4 → database platform, migration runner, schema and probes; 1.17 → shell layouts, router and focus, QueryState and offline; 1.18 → ownership check, merge gate, accept-slice; 1.19 → generator, trace default set, release and manual evidence; 4.10 → grid and blocks, block interactions, keyboard and Ledige tider). This raises the count from 65 to 75 stories.
