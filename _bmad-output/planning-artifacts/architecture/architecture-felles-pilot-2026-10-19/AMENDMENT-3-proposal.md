# Amendment 3 (approved by Jo with option (a), applied) — ownership build mode, gate prerequisites and release mechanics

## Architecture clarifications (spine text)

**A3-1 Ownership has an S00 build mode (blocker).** The Index and `ownership.json` say "one slice per path", yet S00 must create stubs, seam entries, barrels and frozen files that other slices own, and the gate rejects a candidate that spans several slices, so the first real gate run (S00 itself) would fail. Rule: "Each path has one owner at any time. A path that S00 creates for another slice is recorded as `{ path, owner: SNN, createdBy: S00 }`; S00 may create and edit it until `s00-accepted`, and only the owner afterwards. Until `s00-accepted`, slice S00 owns every frozen path and every `createdBy: S00` stub (no `Freeze-Approved` is needed inside S00 except for `packages/contracts/**` and migrations after Gate S00-CP), and `--print-slice` ignores `createdBy: S00` stubs on `slice/s00`. A `Fixes: N.M` commit on `slice/s07` counts as slice S07 for derivation."

**A3-2 The gate checks prerequisites and review (high).** AD-20 says the gate runs `verify:full`, the ownership check and the shared set; it does not enforce ORK-02 or PIL-12/ORK-07. Rule: "The gate refuses a candidate whose prerequisite slices (`dependsOn` in `requirements.json`: S01 and S02 need S00; S03 needs S01 and S02; S04, S05 and S06 need S03; S07 needs S04, S05 and S06) lack an `sNN-accepted` tag, and refuses when any story of the slice lacks `implemented`, `tested` and `reviewed` ledger entries citing commits reachable from the candidate tip. The candidate is a merge commit of the slice tip into `main`, so slice commits keep their SHAs; a story's ledger entries stay valid while no later commit changes a path in that story's Owns cell."

**A3-3 CI on slice branches (high).** AD-27 runs `verify:full` (including the trace check) on every push, which is red by design on an incomplete slice. Rule: "On `slice/sNN` branches CI runs `verify` (with the ownership check) and the Playwright suite on all three operating systems; the trace step reports `INCOMPLETE <slice> <missing parts>` without failing the job until a commit carries the trailer `Slice-Ready: SNN` or the job is the merge-gate candidate; on `main` and at the gate it is blocking."

**A3-4 S07 landing and release (high).** The macOS evidence for NFR-01 is circular (the cited CI run would need the evidence file that cites it), `accept-slice S07` would run `verify:full`, and `verify:release` has no trigger. Rule: "NFR-01 is evidenced by `manual-evidence/NFR-01.md` citing the `smoke.mjs --require-full` step of the macOS job on the parent commit (that step runs independently of the trace step); `accept-slice.mjs S07` runs `verify:release`; a workflow `release.yml` triggers on the tag `s07-integrated` and runs `verify:release`; the gate sets `FELLES_FORBID_501=1` for S07."

**A3-5 SHOULD parts do not block landing (medium).** PRD §6 says SHOULD items are last-in-slice and become residual work if undelivered, but a whole-slice gate would block on them. Rule: "`requirements.json` marks each part `MUST` or `SHOULD`; the default verification set and the gate require MUST parts only; `--release` lists missing SHOULD parts as residual work."

**A3-6 `Freeze-Approved` is verifiable (medium).** Rule: "The trailer value is a pilot-log entry id (`Freeze-Approved: PL-<date>-<n>`) that `check-ownership` finds on `main`."

**A3-7 Gate S00-CP has a state (medium).** Rule: "PIL-09 is evidenced by the pilot-log entry (outside trace, not a `requirements.json` part); sprint-status carries a key `gate-s00-cp` that the orchestrator sets, and Epic 1 stories 1.8 onward stay `blocked` until it is `done`."

**A3-8 Schedule DTO in its own contracts file (medium).** Rule: "The schedule DTO lives in `packages/contracts/src/schedule.ts` (S00 creates a draft; S03 owns it until `s03-accepted`); `activity.ts` and `dashboard.ts` are `createdBy: S00` stubs owned by S03 until `s03-accepted`; the frozen `index.ts` re-exports all."
