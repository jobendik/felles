# Spine Pair Review — felles-pilot

Reviewed: `DESIGN.md`, `EXPERIENCE.md`, `.memlog.md`, `reconcile-brief.md`, `mockups/` (9 files), `.working/` (16 files), against `prd.md` (final) and `docs/requirements.md` v1.0 Part A, with the four bmad-ux example spines and `design-md-spec.md` as shape calibration.

## Overall verdict

The pair is a usable contract: every `{path}` reference resolves, the eight UI-1 surfaces and all four user journeys are specified with protagonists, climaxes and failure paths, the glossary (statuses, Utløpt, Reservert, roles) is identical across spines and sources, and nothing in either file alters an approved requirement (Part A, CR-1..CR-4). What stops it being *strong* is a small set of load-bearing decisions left to the implementer: the Booking detail sheet has no anatomy or states, the booking date control is never named, the slot picker as written cannot express a 30-minute booking, and a handful of visual specs (toast icon colours, today-column wash, 11px tab labels) bypass the token system. No critical findings; three high, which are each a paragraph to fix.

## 1. Flow coverage — adequate

Checked: UJ-1…UJ-4 (PRD §2.3), E2E-01…E2E-10 (spec §10), and the requirement groups that imply a user-facing flow: browse (RES-01), book (BOK-01/05/07), conflict (BOK-03/07), request approval (BOK-05), approve (APP-02), reject incl. expired (APP-02/04, CR-3), cancel own (BOK-06), admin cancel with reason (BOK-06, DEC-07), create/edit/archive resource (RES-03/04), login (AUT-01). The end-of-section `stateDiagram-v2` matches the spec status model exactly.

### Findings

- **low** Edit resource (RES-03 "opprette og redigere") has no flow or step; Flow 6 covers create and archive only; "Rediger" appears once in the Table row. *Fix:* one sentence in Flow 6 step 2 ("He reopens the row with Rediger; the same sheet, prefilled; Lagre") is enough.

## 2. Token completeness — adequate

### Findings
- **medium** Three colour values live only as hex literals in prose with no token: today's column wash `#FAFBFF` (Components → Calendar), toast icon greens/reds `#7EE2A8` / `#FF9B93` (Components → Toast). A consumer extracting from frontmatter will not find them; a consumer reading prose cannot reference them by name. *Fix:* add `surface-today`, `success-on-dark`, `danger-on-dark` to `colors` and reference them.
- **medium** Type sizes used in Components that are not typography roles and break DESIGN.md's own rule "Body text never drops below 13px; 12px is reserved for the compact roles named above" (Typography → Rules): tab bar label "11px 500" (Tab bar), avatar initials "12/32 600" (Avatar), week-strip day number "15/20 600" (Week strip), calendar header day number "16/22 600" (Calendar), top bar title "18/24 600" (Top bar, which is `h2` with a different line-height), badge and slot "`caption` 500" (caption is weight 400). *Fix:* either add roles (`tab-label`, `numeral-sm`, `numeral`, `caption-strong`) or map to existing ones (top bar title → `h2`; day numbers → `h3`/`body-strong` with `tabular-nums`) and amend the 13px rule to name the exceptions.
- **low** `shadow-sm` / `shadow-md` / `shadow-lg` are used as component token values (`card.shadow: 'shadow-sm'`, `sheet.shadow`, `dialog.shadow`, `toast.shadow`) but are defined only in Elevation & Depth prose. The design.md spec has no shadow key, so this is permissible, but the values are then not machine-extractable. *Fix:* add an `elevation:` (or `shadows:`) block in frontmatter, or put the rgba values inline in the component objects.
- **low** `calendar-block-other-pending` (hatched neutral, dashed edge) and the "Arkivert", "kind" badges are described in prose but have no component token, unlike their siblings (`calendar-block-other`, `badge-approval`). *Fix:* add the three objects for symmetry so the resolver sees the full set.
- **low** Alert (inline) border is "1px border in the family's mid tone" — no family has a token called mid tone (each has strong / subtle / on-subtle). *Fix:* name it (`{colors.warning}` etc. at 1px, or add `-border` tokens).
- **low** `surface-overlay` alpha (48%) is stated in a YAML comment and in prose, not as a value. *Fix:* `surface-overlay: 'rgba(23,27,34,0.48)'` or an `overlay-alpha` token.

## 4. State coverage — adequate

Checked: each of the nine IA routes and six overlays for cold-load, empty, error, denied, 404, submitting, conflict, success, disabled, offline. Routes are strong: every route row in State Patterns names loading, empty and error/denied treatments with Norwegian strings; global 401/403/404/offline are covered once; "No optimistic updates" is committed; UI-4 confirmation rules are explicit and reasoned (approve needs none).

### Findings
- **high** (same root as 3) **Booking detail sheet** has no state row at all. *Fix:* see §3 first finding.
- **medium** **Slot picker** cannot express the minimum legal booking. Rules: "First activation sets the start; the next sets the end … activating the start again clears" (EXPERIENCE.md → Slot picker). Flow 1 shows the end slot is inclusive (10:00 then 10:30 = 10:00–11:00). A 30-minute booking (BOK-02 minimum) would need start = end, which the rules define as *clear*. *Fix:* state the inclusive-end semantics explicitly and give the 30-minute path ("a start with no end is a 30-minute booking; the summary reads 'Valgt: 10:00–10:30, 30 min'; activating the start again clears only when an end is set", or equivalent).
- **medium** Contradiction on client-side disabling: Interaction Primitives → Forms says "Submit buttons stay enabled until the request starts, so users get server-side messages", while Reason dialog says "Submit disabled until valid" and the Booking sheet disables Book when the resource was archived. The Reason dialog behaviour is right (APP-02 reason is required), but it must be stated as the exception. *Fix:* rephrase the Forms primitive: "…except where a required field is empty (reason, purpose), where the button is disabled with the reason visible".
- **low** Booking sheet lacks: date outside window / past date (depends on §3 date control), resource select empty (no active resources, admin-only reality — covered for Ressurser, not here), and the 409 shape for a *pending* request (identical to confirmed; say so). *Fix:* one Notes-column sentence.
- **low** Godkjenninger: `BOOKING_STARTED` (APP-03, CR-3 item 1) can still arrive if the start passes while the admin has the row open; the row handles "already handled" only. *Fix:* "…or 'Starttidspunktet er passert. Forespørselen kan bare avslås.' and the row re-renders as Utløpt".
- **low** Hjem admin panel: the top-3 list excludes zero-count resources (DEC-04) so it can be empty or shorter than three; no treatment. *Fix:* "Ingen bekreftede bookinger de neste 7 dagene." in the tile.
- **low** Confirm dialog: cancel refused because start passed meanwhile (BOK-06) has no treatment (archive refusal does). *Fix:* mirror the archive pattern: dialog closes, inline alert on the row.
